# ToxAgent agent evaluation (plan §16)

The initial 50-task set and the deterministic grading layer. The model rubric
and SME graders (plan §16.4) are **not** here — a task that needs them lists
them in `graders` and the runner records those dimensions as `deferred`, never
as pass.

## Layout

| Path | What |
|---|---|
| `schema/task.schema.json` | the `eval-task-v1` contract (Phase 0) |
| `tasks/*.json` | 50 tasks — one file each, generated by `build_tasks.py` |
| `fixtures/*.json` | frozen, content-hashed predictor/evidence bundles (`build_fixtures.py`) |
| `graders/` | `run`, `schema`, `state`, `transcript`, `hard_gates` — pure functions |
| `schema/task.schema.v3.json` | `eval-task-v3`: v1 plus pack, risk tier, runtime/feature requirements, fault injection, budget, expected artifacts, grader and trial policy, provenance |
| `packs/*.json` | declared task packs (`eval-pack-v1`): `core`, `regression`, `security`, `report`, `ocr`, `sealed` — owner, task directories, suites |
| `regression/tasks/`, `packs/*/tasks/` | hand-authored tasks outside the generated core set |
| `task_packs.py` | discovery, v1 -> v3 adapter, suite hash, conservation check |
| `graders/` (Wave 1) | also `trajectory`, `budget`, `outcome_split`, `decision_state`; `GRADER_REGISTRY` versions every grader |
| `trace.py` | `eval-trace-v1`: the one trace projection every driver and grader shares |
| `manifest.py` | `eval-manifest-v2`: effective product, source, environment, discovery, release eligibility |
| `architecture_inventory.py` | generates `docs/architecture-inventory.json` |
| `runner.py` | loads, executes, grades, writes a manifest + results + traces |
| `manifests/` | run output (git-ignored) |

## Packs, statuses and manifests (TAB-Suite Wave 0/1)

`--packs` selects declared packs (`core,regression` by default; `all`, or
`suite:pr|nightly|release` for a suite's packs). Every JSON file under a
selected pack either loads or is reported `invalid`; the run fails on any
invalid task, and on any discovered task that lands in no result bucket:

    discovered = pass + fail + skipped + invalid + infra_error

`infra_error` is the environment ending a trial (a driver transport error, or a
run failing with an infrastructure code the task did not ask for). It is never
a pass and never a product failure. A skip always carries a typed reason
(`runner.SKIPPED_REASONS`), including `feature_requirements_unmet` when the
deployment's effective flags/topology are not the ones the task was written
for, and `not_selected` for `--task` filtering.

The manifest (`eval-manifest-v2`) records the deployment's
`effective-product-v1` document — read in process for `scripted`, over
`GET /v1/system/effective-product` for a live stack — plus the source commit
and dirty flag, host resources, grader versions and pack discovery.
`release_evidence.blockers` lists every reason the run cannot be attached to a
release decision; a scripted run always has at least one. Answers are reported
as `first_pass` / `accepted_after_correction` / `fallback` per trial, and the
`outcome_split` grader never counts a fallback as an agent pass.

The sealed pack's content never lives in this repository: set
`TOXAGENT_SEALED_TASKS_DIR`; only tasks whose `sealed_id` the pack manifest
declares are admitted. Absent, the pack is `not_evaluated`.

## Cutover and release tooling (Wave 4/5)

| Command | Produces |
|---|---|
| `python -m evals.paired --baseline A --candidate B --expect-change flags.report_orchestrator_v2` | `eval-paired-comparison-v1`: per-task transitions, McNemar p, confounds, critical regressions |
| `python -m evals.conformance --out conformance.json` | `control-plane-conformance-v1`: worker/lease/fencing/cancel/backpressure drills; `not_covered` ones need a real multi-replica stack |
| `python -m evals.calibration --sme gold.jsonl --judge verdicts.jsonl --out calibration.json` | `judge-calibration-v1`; `calibration.drift(previous, current)` flags a judge that moved |
| `python -m evals.scorecard --level release --manifest … --conformance … --calibration … --signoff …` | `toxagent-release-scorecard-v1`, HMAC-signed with `TOXAGENT_RELEASE_SIGNING_KEY`; `--verify` checks it |
| `python -m evals.regression_from_run --base-url … --token … --session … --run … --task-id …` | a scrubbed `eval-task-v3` review draft in `regression/drafts/` (not a pack until reviewed) |

Semantic judging is opt-in on a run: `--judge-command` (an external, non-product
model reading `{request, verdict_schema}` on stdin) or `--judge-recorded DIR`,
plus `--calibration` to let calibrated rubrics gate.

## Category budget (plan §16.2)

`numeric_fidelity 12 · endpoint_semantics 8 · report_qa 10 ·
evidence_synthesis 8 · failure_recovery 6 · adversarial_session 6`

Enforced by `tests/unit/test_eval_tasks.py`, which also checks every task

## Running

From a fresh clone, the whole backend suite plus three scripted eval trials is
one command — `make -C backend/control test` (see `backend/control/Makefile`),
which needs no pre-existing workstation virtualenv.

```bash
# CI path — deterministic tasks only, no model. pass^3 over the subset.
python -m evals.runner --runtime scripted --trials 3

python -m evals.runner --list          # det = runs in CI, llm = needs a runtime
python -m evals.runner --task fail-01-predictor-503 --task qa-09-out-of-scope-clinical-advice
```

`--runtime scripted` executes only the tasks whose outcome is deterministic
without an LLM:

- analysis-failure tasks (`fail-01..03`) — predictor 503 / malformed body /
  invalid SMILES;
- routing tasks (`qa-09` out-of-scope, `qa-10` clarification-required).

The other 45 are reported `needs an agentic runtime` and excluded from the
pass rate. To run them, stand up the full stack (`scripts/run_local_phase3.sh`)
and point the suite at it:

```bash
python -m evals.runner --runtime opencode \
  --base-url http://127.0.0.1:8000 --token dev-local --trials 1
```

`RemoteHTTPDriver` (`runner.py`) drives those tasks over the product's own HTTP
API. It talks to whatever predictor that stack is configured with — normally
the real ToxPred, not the frozen fixture — so the fixture mode defaults to
`predictor_integration` and `is_live_compatible` excludes any task that pins an
exact `source_value`. What runs live is graded on structure and wording
(required/forbidden limitations, must/must-not-mention, hard gates), which hold
regardless of the exact numbers. Two runs are comparable only in the same
fixture mode, and the manifest records which one was used.

## Hard gates (plan §16.5)

A task fails outright if any gate it lists trips, regardless of quality score.
The gates reuse the product's own checks where one exists — the
`prohibited_claims` regexes, the numeric transform/tolerance rule — so a gate
cannot drift from what `submit_grounded_answer` enforces at commit time.

## Editing

- Change a task → edit `build_tasks.py`, re-run `python -m evals.build_tasks`.
- Change a fixture → edit `build_fixtures.py`, re-run `python -m evals.build_fixtures`
  (it rewrites `content_sha256`); or `python -m evals.frozen --rehash` after a
  hand edit. `load_fixture` refuses a fixture whose hash no longer matches.
- Manifests record `eval_suite_hash` over every task + fixture + the schema, so
  a silent task edit shows up as a new suite hash in the next run.
