## Part B — Product feature audit and minimal UI

### B1. What the UI exposes today

| Screen | Options exposed |
|---|---|
| **Sidebar** | New session · search · running tasks · session list by date · load more · footer: *Phân tích nhanh*, *Tất cả sessions*, *Cài đặt*, *Giới thiệu* |
| **Workbench header** | Rename · status · **Session config popover** (agent-model select + one model select per predictor endpoint + Save) · *Kết quả* toggle |
| **Composer** | Text · 3 buttons (SMILES / Ảnh / Vẽ) · separate SMILES field · **intent select (6 values)** · **explanation mode (3 radios)** · **advanced popover**: endpoint checkboxes (3), Tox21 assay checkboxes (12), hERG threshold override (expert) |
| **Empty session** | 3 cards duplicating the 3 composer buttons |
| **Artifacts panel** | 3 tabs (*Sources*, *Results*, *Điều tra*) + artifact picker select |
| **Run inspector** (developer mode) | 4 tabs: timeline, runtime, validation, raw JSON |
| **Quick Predict** | Single/batch toggle · endpoint chips · model select per endpoint · **compare-models mode** with per-model checkboxes · threshold override (expert) |
| **Settings** | Connection card · developer-diagnostics toggle · AI provider form (provider, model, name, base URL, auth mode, API key, test/delete) · expert-mode toggle |
| **Landing** | 9 full-screen marketing sections (hero, how-to, team, tech stack, scale, research source, case study, collaborators, affiliation) |
| **About**, **Sessions** | Separate pages |

Backend: 15 rollout flags (`backend/control/src/toxagent/flags.py`); 2 default on
(`runtime_profile_selector_v2`, `normalized_usage_v2`), 13 default off.

### B2. Where the excess comes from

1. **Router internals exposed as user choices.** The intent select and explanation mode make the user do the router's job; `auto` / `on_demand` are already the defaults.
2. **Choices with only one valid answer.** Each endpoint has one admitted model, so the per-endpoint model selects (session popover, Quick Predict) and compare mode offer nothing.
3. **Expert/developer controls in the main flow.** Threshold override is rejected by the backend unless the token has the `expert` role; both toggles live in Settings but their controls leak into the composer and Quick Predict.
4. **Flag-gated features shown unconditionally.** The *Điều tra* tab is always visible, although `scientific_case_v1` is off by default.
5. **Duplicated entry points.** Empty-state cards = composer buttons; *Tất cả sessions* ≈ sidebar list + search; About ≈ Landing.

### B3. Target (minimal)

| Screen | Keep | Remove / move |
|---|---|---|
| **Composer** | Text box; one **+** attach menu (SMILES · Ảnh · Vẽ); SMILES shown as a removable chip when detected or prefilled; send | Intent select (always `auto`); explanation radios (always `on_demand`; the user asks for an explanation in text); advanced popover entirely (endpoints = all served; assay picking only mattered for `required`; threshold override becomes API-only) |
| **Workbench header** | Title/rename, status, *Kết quả* | Session config popover. AI profile becomes one default in Settings; predictor binding disappears until a second model is admitted |
| **Empty session** | One line of guidance + 2–3 example prompts | The 3 duplicate cards |
| **Artifacts panel** | One panel: the selected result, sources listed under it | Tabs; *Điều tra* only when `/health/ready` reports `scientific_case_v1` on |
| **Run inspector** | As is, behind developer mode | — |
| **Quick Predict** | Single/batch, SMILES/file input, result. This is the only screen that works in the default predictor-only stack, so it stays | Per-endpoint model select, compare mode, threshold override |
| **Settings** | Connection + *Disconnect*; AI provider (provider, model, API key; base URL only when the provider needs it); *Advanced* collapsed: developer diagnostics | Expert-mode toggle; auth-mode select (derive from provider); display-name field |
| **Sidebar footer** | *Phân tích nhanh*, *Cài đặt* | *Tất cả sessions* (verify the sidebar search covers it — today it only searches loaded rows), *Giới thiệu* |
| **Landing / About** | Hero + token entry | 8 marketing sections and the About page (or keep one short About section) |

Net effect on the composer: from ~25 visible/clickable controls to 3 (text, +, send).

  `checkbox.tsx` once the composer stopped using it; 23 npm packages. `openchemlib` stays
  (peer dependency of `react-ocl`).

  detected in the text shows as a chip that can be dismissed (the message then goes as
  text only); an explicit SMILES shows as an editable chip; a sentence with several
  candidates offers them as buttons. Always sends `intent_hint: auto` and
  `explanation_mode: on_demand`, and leaves `endpoints` to the server's
  `default_endpoints`. The hERG threshold override is a small popover shown only in
  expert mode (B6.2).
- **B3 header.** `SessionConfigPopover` removed. Settings holds one default AI profile
  (`toxagent.default_ai_profile.v1`); `useSessionProfileSync` writes it into the
  session's settings before the first send, and unpins a profile that is no longer
  ready. A user who never picks a default keeps whatever the session already had.
  Per-endpoint predictor binding disappears with the popover (one admitted model per
  endpoint).
- **B3 empty state.** One line of guidance and three example prompts that fill the
  composer; each is tested to contain exactly one molecule.
- **B3 artifacts panel.** No tabs: result picker, the selected result, then *Nguồn*
  (sources open in the same viewer). *Điều tra khoa học* appears, collapsed, only when
  the session has a scientific case — `/health/ready` does not report flags, and an
  empty case list is exactly the flag-off state.
- **B3 Settings.** AI card: default-profile select, profiles, and a form of provider,
  model, API key, plus base URL only when the provider has no fixed endpoint. The auth
  mode follows from whether a key was given; the display name defaults server-side.
  *Nâng cao* (collapsed): developer diagnostics and the expert-mode toggle.
