# Security Policy

## Supported versions

This repository is a reference service. Only the latest version on `main` is considered supported.

## Reporting a vulnerability

Please do not open public GitHub issues for security problems.

Send reports to `security@example.com` with:

- a clear description of the issue
- reproduction steps or proof of concept
- impact assessment
- any suggested remediation

## Response targets

- Initial acknowledgement: within 2 business days
- Triage decision: within 5 business days
- Remediation plan: within 10 business days for confirmed issues

## Scope

Examples of in-scope issues:

- authentication or authorization bypass
- injection vulnerabilities
- data exposure through logs or APIs
- denial-of-service vectors caused by unbounded resource use
- insecure defaults in deployment guidance

Out of scope:

- theoretical issues without a realistic exploitation path
- dependency advisories that are not reachable in this codebase
- best-practice suggestions that do not expose a concrete risk

## Coordinated disclosure

Please allow time for remediation before public disclosure. We will credit reporters who want acknowledgment once a fix is available.
